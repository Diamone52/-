# Пульс — контроль тренировочного процесса

Курсовое задание, тема 16: десктопное приложение для контроля тренировочного процесса
(трекер тренировок) с входом/регистрацией пользователей и хранением данных в SQL-базе.

## Технологии

- **C# / WPF**, .NET 8 (Windows)
- **Microsoft SQL Server** (LocalDB) — `Microsoft.Data.SqlClient`
- Хеширование паролей — PBKDF2-HMACSHA256 со случайной солью

## Структура решения

```
PulseTracker.sln          — файл решения Visual Studio
README.md                 — этот файл
PulseTracker/              — проект приложения

├── App.xaml(.cs)          — точка входа, инициализация базы данных
├── LoginWindow.xaml(.cs)  — окно входа и регистрации
├── MainWindow.xaml(.cs)   — главное окно (обзор, дневник, планы, упражнения, прогресс)

└── Dialogs/               — окна добавления/редактирования упражнений, планов, тренировок
```

## Как запустить

1. Установите **.NET 8 SDK** (Windows): https://dotnet.microsoft.com/download
2. Установите **SQL Server Express LocalDB**, если его ещё нет. Проще всего — через
   Visual Studio Installer: отметьте компонент **«Разработка классических приложений .NET»**,
   в его дополнительных компонентах справа найдите **«SQL Server Express LocalDB»** и
   поставьте галочку. Либо отдельно: https://learn.microsoft.com/sql/database-engine/configure-windows/sql-server-express-localdb
3. Откройте `PulseTracker.sln` в Visual Studio **или** в терминале из корня решения:
   ```
   cd PulseTracker
   dotnet restore
   dotnet run
   ```
4. При первом запуске приложение само создаёт базу данных `PulseTrackerDb` на экземпляре
   `(localdb)\MSSQLLocalDB` (файлы `.mdf`/`.ldf` — в `%AppData%\PulseTracker\`) и открывает
   окно **регистрации** — создайте ФИО, почту и пароль. После входа приложение автоматически
   заполнит базу демонстрационными данными (4 плана тренировок).

### Просмотр базы данных вручную

Базу можно открыть в **SQL Server Management Studio (SSMS)** или во вкладке
**«Обозреватель SQL-объектов»** Visual Studio, подключившись к серверу:
```
(localdb)\MSSQLLocalDB
```
База данных будет называться `PulseTrackerDb`.

## Роли пользователей

- **Пользователь** — обычный аккаунт, полный доступ к своим тренировкам, планам, прогрессу.
- **Тренер** — дополнительно видит раздел «Пользователи»: список всех зарегистрированных
  аккаунтов и может назначить любому из них тренировку на основе одного из его планов.
  Зарегистрироваться тренером можно только со специальным 4-значным кодом: **9203**
  (поле «Код тренера» появляется на экране регистрации при выборе роли «Тренер»).
- **Администратор** — встроенная роль с теми же правами, что у тренера; создаётся один
  раз автоматически при первом запуске (зарегистрироваться администратором через форму нельзя).

Учётная запись администратора по умолчанию:

| ФИО            | Почта                     | Пароль     |
|----------------|----------------------------|------------|
| Администратор  | admin@pulsetracker.local  | admin123   |

## Раздел «Профиль»

Показывает ФИО, почту, роль, дату регистрации и полный список ваших планов тренировок.

## База данных

База данных **`PulseTrackerDb`** создаётся автоматически при первом запуске на локальном
экземпляре SQL Server — `(localdb)\MSSQLLocalDB` (файлы `.mdf`/`.ldf` хранятся в
`%AppData%\PulseTracker\`).

Схема — см. `PulseTracker/Database/schema.sql`. Основные таблицы:

| Таблица            | Назначение                                              |
|--------------------|----------------------------------------------------------|
| `Users`            | учётные записи (логин, хеш пароля, соль)                 |
| `Exercises`        | справочник упражнений пользователя                        |
| `Plans`            | планы (шаблоны) тренировок                                |
| `PlanItems`        | упражнения внутри плана (подходы/повторы/вес)             |
| `Sessions`         | записи дневника тренировок                                |
| `SessionExercises` | упражнения, выполненные в конкретной тренировке           |
| `SessionSets`      | подходы (сеты) внутри выполненного упражнения             |

Все таблицы приложения ссылаются на `Users.Id`, поэтому у каждого пользователя —
собственный, изолированный набор данных.
